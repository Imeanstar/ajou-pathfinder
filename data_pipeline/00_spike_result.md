## Task 0-1: 아주허브 프로그램 수집

**방법:** `https://hub.ajou.ac.kr/ncrProgramAppl/a/m/getProgramDetail.do?npiKeyId=NCR{12자리 숫자ID}` 순회.

- **ID 형식 주의:** `NCR` + **12자리** 숫자(0-padded). 13자리로 잘못 패딩하면 전부 오류 페이지(3392바이트 고정)를 반환하므로 응답 크기로 유효성 판별 가능(`size > 10000` → 유효).
- **유효율:** ID 2000~2100 구간에서 16개 샘플 중 15개 유효 (93.75%). ID 1(무효), 100(유효, 대용량), 500·1500·3000·5000·8000(무효) — **활성 프로그램이 2000번대에 몰려 있음**. 정확한 하한/상한은 Phase 2에서 순차 탐색으로 확정.
- **robots.txt:** 없음(404).
- **필드 구조:** 표가 아니라 `<dl class="program_contentbox"><dt>...</dt><dd><strong>라벨</strong>값</dd>...</dl>` 패턴. `<strong>라벨</strong>` 뒤 텍스트를 정규식/BeautifulSoup으로 추출.
- **확보 가능 필드:** 프로그램명, **카테고리 3단계**(예: `학습역량 강화 〉 자율활동 〉 교내.교외` — 아주대가 이미 분류해둔 체계! `주제기획서.md`의 자체 역량 태깅 부담을 줄이는 데 활용 가능), 운영부서, 모집기간, 활동기간, 참여학과, 참여학년, 참여대상, 장소, 실시유형, 문의전화, 모집인원/대기인원.
- **부가 발견:** 이미지·첨부파일이 많은 프로그램은 응답이 470KB까지 커짐(id=100) — fetch 시 텍스트 영역만 추출하고 나머지는 버릴 것.

**샘플:** `spike_samples/hub_program_sample.html`

## Task 0-2: 교육과정(과목) 데이터

**최초 가정이 틀렸음 — 설계 변경.**

`주제기획서.md`/실행계획 원안은 "요람 PDF → pdfplumber 표 파싱"이었다. 실제로 확인해보니:

1. 요람 게시판(`ajou.ac.kr/kr/bachelor/bulletin.do`)의 PDF는 게시글 제목 그대로 **"학사력·총람·기구표·학교법인"만** 담고 있다(52쪽). 학과별 교육과정(목차상 700쪽대)은 **여기 없다.**
2. 대신 **학과 홈페이지에 교육과정표가 HTML로 직접 존재**한다: `https://software.ajou.ac.kr/sub02/sub02.php` ("교과과정" 메뉴).
3. 이 페이지는 **PHP 세션 쿠키가 있어야 응답한다.** 쿠키 없이 직접 요청하면 타임아웃(무응답)으로 멈춘다. 해결: 루트(`https://software.ajou.ac.kr/`)에 먼저 요청해 `PHPSESSID` 쿠키를 받은 뒤, 그 쿠키를 담아 재요청.

```bash
curl -s -c cookies.txt -o /dev/null "https://software.ajou.ac.kr/"
curl -s -b cookies.txt "https://software.ajou.ac.kr/sub02/sub02.php" -o curriculum.html
```

4. 표는 표준 `<table><tr><td>` 구조(24개 table, 350개 tr). `rowspan`/`colspan`이 섞여 있어 (예: `<th rowspan="3">전공필수</th>`가 여러 행에 걸침) 파싱 시 rowspan 추적 로직이 필요함 — BeautifulSoup + 수동 rowspan 카운터로 처리.
5. 컬럼: 과목명 / 학점 / 시간 / (빈칸, 아마 실습시간) / (빈칸) / 이수구분(전공필수 등) / 과목명 / 학점 / 시간 / 선수과목.
6. **부가 발견:** `sub02/sub01.php` = "교육과정 체계"(로드맵 다이어그램), `sub02/sub03.php` = "졸업요건" — 같은 세션 쿠키로 전부 접근 가능.

**샘플:** `spike_samples/sw_curriculum.html`, `spike_samples/session_cookies_example.txt`

**실행계획 반영:** `docs/plans/2026-08-20-실행계획.md`의 Task 2-3을 "요람 PDF 파싱"에서 "학과 홈페이지 HTML 표 파싱(세션 쿠키 필요)"으로 갱신 완료. **PDF 파싱보다 쉬워졌으므로 리스크가 오히려 낮아짐.**

## Task 0-3: 졸업요건 수치 재검증

**`주제기획서.md` 5-1에 적힌 "2024학번 140학점 / 2025학번 128학점" 표는 부정확한 것으로 확인됨** (자동 요약 과정의 오독으로 추정).

`sub02/sub03.php` 원본 표("과정별 필수 이수학점 구성 현황")를 직접 확인한 결과, 실제 구분 축은 **입학년도가 아니라 "과정" 종류**다:

| 구분 | 아주인성 | 영어1,2 | 글쓰기 | 영역별교양 | SW커리어세미나 | 수학 | 기초과학 | 전공필수 | 전공선택 |
|---|---|---|---|---|---|---|---|---|---|
| 심화과정 | 1 | 6 | 3 | 9 | 1 | 12 | 7 | 36 | **37** |
| 일반과정 | 1 | 6 | 3 | 9 | 1 | 12 | 7 | 36 | **10** |
| 복수과정 | (제1전공 기준 이수) | | | | | | | | 1... (표 잘림, 재확인 필요) |

**⚠️ 아직 완전히 확정되지 않음.** 표가 더 이어지고(복수과정 이후 행 미확인), 입학년도별 총 이수학점 총계는 이 표만으로는 계산 불가 — 별도 섹션에 있을 가능성. **Phase 1(팀 결정) 전에 이 페이지 전체를 한 번 더 사람이 직접 열어서 대상 학번의 정확한 총 이수학점을 확정할 것.**

**샘플:** `spike_samples/sw_graduation_reqs.html`

## 종합 판단

Phase 0의 목적("이대로 진행해도 되는가")에 대한 답: **YES, 진행 가능.** 데이터 확보 리스크는 애초 우려보다 낮다(PDF 파싱보다 HTML 파싱이 쉬움). 다만:

1. **졸업요건 정확한 수치는 재확인 필수** (위 표 미완성)
2. 스크래핑 시 `software.ajou.ac.kr`은 **세션 쿠키 선요청 필수** — 이걸 빠뜨리면 전체 요청이 타임아웃으로 멈춰서 원인 파악에 시간을 뺏길 수 있음
3. 아주허브 ID 범위는 Phase 2에서 실제 순회로 정확히 확정
